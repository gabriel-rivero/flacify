# v1.0 plan — utility

Status: working plan, reviewed against the code 2026-11-18. Supersedes the v1.0
sketch in [`roadmap.md`](roadmap.md#v10--utility), which stays as the summary. The
roadmap's `v0.4-plan.md` is the shape this file copies: decisions first, then waves
with an acceptance test each.

Decisions taken 2026-11-18, after checking this plan against the code: the bounded
path is opt-in (`--live`), V4-6's remainder is deferred, the 60-minute fixture is
synthesised, S1 listens to two library tracks, and items land as local branches
merged `--no-ff`. The corrections that came out of that check are in
[What the review changed](#what-the-review-changed-2026-11-18); where they disagree
with the text below, the review section wins.

## What 1.0 is

The bottom-right cell of the matrix. Everything before it is one file, played from a
buffer the app made earlier. 1.0 is the first release where audio arrives while it is
still happening, and the first one that is worth pointing at a library rather than a
file.

| | file source | live source (capture) |
|---|---|---|
| **render-ahead** (producer unthrottled) | shipped in 0.2 | n/a |
| **bounded queue** (producer throttled) | **1.0** — `--live` | **1.0** — the sink |

Four features, one pipeline. What changes between them is the source and the policy,
which is the reason this file spends its length on the queue rather than on any single
feature.

## What the roadmap gets wrong, and what replaces it

1. **The latency presets are real, and the quality is the unknown.** The sidecar takes
   `channels, frames` per request and derives the latent shape for that window
   (`tools/worker.py:142-150`), and `Pipeline::new` accepts any window
   (`crates/core/src/pipeline.rs:62-95`). `GRANULE = 30_720` is 0.64 s
   (`crates/core/src/lib.rs:23`), so the roadmap's 0.64 / 1.28 / 2.56 / 5.12 s are 1, 2,
   4 and 8 granules. What is unknown is whether the model sounds acceptable at one and
   two granules, and what each costs per call. S1 answers that before anything is built
   on it. The window is a `const` today (`render.rs:50-52`), so the presets also need it
   to become a parameter through render, cache key and source tier (D6, D11).
2. **The sink is a cable the user installs, not a driver we ship.** macOS has no
   loopback device; Windows has no cpal loopback at all; Linux has PipeWire. A driver per
   platform is three projects, each needing a certificate we do not have. 1.0 documents
   BlackHole (macOS) and routes to whatever the user installed (D4). Windows is
   documented as unsupported in 1.0 rather than half-built.
3. **The builds exist.** The roadmap's v1.0 row still lists "Windows/Linux builds"; 0.4.0
   already shipped `.exe`, `.dmg`, `.deb` and an Arch package. The build work in 1.0 is
   single-sourcing the version and adding a macOS CI job, not adding platforms.
4. **The deletion waits for 1.1.** The progressive path already falls back to the dry
   side when starved (`player.rs:343-349`); only the segmented path stalls with silence.
   The bounded rings arrive for `--live` and the sink, and the default play of an
   uncached file keeps the progressive path, which still holds a whole decoded track and
   a never-evicted frontier (`frontier.rs:40-45`). Making the bounded path the default is
   a separate change, after A2 has evidence, and it is not 1.0's promise.

## Decisions

| # | decision | why, and what it rules out |
|---|---|---|
| D1 | **One live pipeline, two feeds.** `Source::Live` takes a `Feed`: the decoder for a file, the capture stream for the sink. The mixer, ramp, A/B and underrun policy are the same code. | The roadmap's two matrix cells differ only in the producer. A second playback path is how the two A/B implementations drift apart (architecture.md:161-162 already warns about this). |
| D2 | **Bounded rings with credit backpressure, and passthrough on starvation.** The producer waits while the wet ring holds more than the buffer budget. A starved playhead plays the dry side from the delay ring, increments a dropout counter, and leaves A/B disabled with a reason until the buffer refills. | Files today hold silence and stall the playhead (`player.rs:358-364`), which is right for a segment miss and wrong for live audio. Never a gap, never a silent stall. |
| D3 | **Latency is a window length, and it is stated, not implied.** A preset selects the model window (1, 2, 4 or 8 granules). The UI prints the resulting latency: window + buffer + device, measured by S3, not derived. | The panes are sample-locked by construction; there is no way to be "low latency" and keep a 5.12 s look-ahead. A user who picks 8 granules is told they are 5 s behind. |
| D4 | **The sink routes between named devices; the user supplies the loopback.** `flacify sink --from BlackHole 2ch --to "External Headphones"`. No driver ships, nothing is bundled, BlackHole stays a documented prerequisite (it is GPL-3.0; we never link or redistribute it). | Rules out Windows in 1.0 (no cpal loopback; a WASAPI backend is its own PR), signing, and any claim about A/V sync. |
| D5 | **Live audio is in-memory and uncached.** No hash, no length, no FLAC, no manifest. Resident cost is the rings: `2 × buffer × 2 ch × 4 B`. | A stream has no `frames()` and no blake3 key (`session.rs:137-143`). The segment machinery is for files and stays that way. |
| D6 | **A preset is a render parameter, so it invalidates the cache.** `window` joins the key the same way `overlap` does. | Changing the window changes the seed lattice and every crossfade; a 5.12 s cache entry cannot answer a 1.28 s request. |
| D7 | **Batch is a job list above `Session`, one file at a time.** Sorted walk, skip a complete cache entry, isolate failures, keep going, exit non-zero if any failed, write a skip/failure list next to the cache. Resume is already free because an interrupted render leaves its segments (`cache.rs:295-297`). | Rules out parallel files: one worker, one GPU, and two renders would halve each other's RTF. A folder drop onto the window maps onto the same list later, not in 1.0. |
| D8 | **A blind test owns the switch.** `ab` disables auto-promotion (`player.rs:241-252`), randomises which excerpt plays first, and records the truth per trial. The report is only offered after the level match is verified inside the run. | Promotion decides the order today, so "blind" would be a lie. A report that assumes the match is a report of the assumption. |
| D9 | **The version has one source.** `Cargo.toml` is read by the release workflow; `release.yml` stops hardcoding `0.4.0` in eight places, and `flacify.iss`/`PKGBUILD` take it as a parameter. | The alternative is releasing a package whose menu says 0.4.0. |
| D10 | **`ui.rs` has one owner for the whole release.** Splitting `draw_transport` into named sections behind a `Panel` seam happens first (F5), so later items add a panel instead of patching one 174-line function. | Three parallel agents editing one `draw_transport` is how the toggle caption loses a word. Panels are added; the file is not concurrently patched. |

## What the review changed (2026-11-18)

The plan was checked against the code before implementation started. These are the
things it got wrong, and the decision that replaces each.

| # | finding | decision |
|---|---|---|
| D11 | **A preset breaks the source tier, not just the cache.** The tier directory is keyed by the file hash alone, and its manifest pins `frames_per_segment`; a different window makes `validate` return an error rather than a rebuild (`source.rs:119-125`, `source.rs:485-491`). Today the second preset would fail. | The tier path includes the frame grid (`window - overlap` × 7), or a mismatch rebuilds it. U1's acceptance runs two presets on the same file, twice. |
| D12 | **Passthrough already exists on the progressive path** (`player.rs:343-349`); only `Source::Segmented` holds silence and stalls (`player.rs:358-364`). | F3 reuses that behaviour for `Source::Live` and does not change progressive. The new work is the rings, the credit, and the counter. |
| D13 | **Bounded memory is opt-in in 1.0.** The default first play stays progressive; 1.1 flips the default after A2. | `--live` is the bounded path. README, roadmap and release notes say the default first play still holds the whole track, so 1.0 does not claim otherwise. |
| D14 | **V4-6's playhead-priority scheduler never landed**, and `render_segments` renders strictly in order (`render.rs:709-719`). A seek into an unrendered region waits for everything before it. | Out of 1.0. A1 seeks after the render completes, and the roadmap says 1.1 owns seek-during-render. |
| D15 | **The sink dies on TCC without a usage string.** The release workflow's `Info.plist` has no `NSMicrophoneUsageDescription`, and macOS kills a process that opens an input device without one. | R1 adds it, and the sink's `.app` path is tested with the shipped plist, not with `cargo run`. |
| D16 | **R2 has a kill criterion but no correction design.** `dsp/resample.rs` is a pure, zero-padded function, so a streaming variable-ratio resampler is new code. | S2 names and measures the correction it ships (ppm trim through a variable-ratio resampler, with drop/insert as the fallback). K1 implements the one S2 proves. |
| D17 | **The docs contradict the repo.** The roadmap still lists platform builds as v1.0 work, `backlog.md` has no v1.0 items, `risks.md` has no drift or TCC risk, and no ADR covers live mode or the sink. | W2 is a docs pass: roadmap v1.0 row, backlog epics, risks R2/R3, and ADR-014 for the live pipeline. |


## Risks, with the trigger that kills the item

| # | risk | spike that answers it | kill criterion |
|---|---|---|---|
| R1 | **The model sounds wrong at one granule.** Trained at 8; short windows give it less context and a worse boundary. | S1 | 0.64 s clearly audible as broken on two of the five measurement tracks → drop that preset, keep the longer ones. If 1.28 s also fails, the sink is a 5.12 s listening feature and the UI says so. |
| R2 | **Capture and playback clocks drift.** Two crystals, ~30-100 ppm apart, is 0.1-0.4 s an hour. The wet ring slowly empties or overflows. | S2 | Drift over 10 minutes > 50 ms after correction, or the correction is audible as a tick → sink ships with a restart-on-drift (a gap every N minutes) and says so, rather than a click. |
| R3 | **macOS refuses the microphone.** BlackHole is an input device, so the app needs TCC permission, and it is unsigned. | S2 | The prompt cannot be satisfied on a signed build we can produce → the sink documents `flacify sink` as a terminal command, where the parent app owns the permission. |
| R4 | **The licence question stays unanswered.** Weights are downloaded at first run and never bundled, which is the documented mitigation (`dependencies.md:162-170`). | S4 (human) | No answer by release → ship unsigned, notice-only, and say in the release notes that the weights are the author's. |
| R5 | **A live file path is only honest above ~1.25x.** The end-to-end renderer measures RTF 0.78 on the M5, and the model load is ~8 s. | S3 | Sustained RTF > 0.85 through the live path on the M5 → `--live` still ships, but it starts in `Marginal` with passthrough armed instead of claiming real time. |
| R6 | **Parallel agents on one audio path.** The A/B ramp, the underrun policy and the seek semantics all live in `player.rs`. | wave review | Any wave whose merged diff changes `Mixer::fill` behaviour without a test that fails on the old behaviour is rejected and redone, not patched. |

## Parallelisation contract

Implementation runs as two agents per wave, plus me. The split is by subsystem, not by
feature, because the hot files are the risk:

| owner | files | why together |
|---|---|---|
| **audio path** | `player.rs`, `live.rs`, `device.rs`, `session.rs`, `ui.rs`, `sink.rs` | one clock, one underrun policy, one ramp, one window drawing it |
| **data path** | `cache.rs`, `batch.rs`, `ab.rs`, `diagnose.rs`, `cli.rs`, `commands/`, docs | no atomics, no callback, testable headless |

- Each agent works in its own worktree under `.claude/worktrees/<item>`, one branch, one
  PR, no shared checkout.
- I merge serially, and after each merge run `cargo fmt --check`, `cargo clippy
  --workspace --all-targets`, `cargo test --workspace --all-targets` in the main checkout.
  A green agent is not evidence; the merge is.
- Each wave gets one independent review on a different model family before merge, pointed
  at the diff and the acceptance row, asked for bugs and logic, not style.
- Interface changes go in the wave brief before dispatch: `Feed`, `Source::Live`, the hold
  API, `LivePolicy`. An agent that needs to change one stops and says so.

## What 1.0 does not include

A driver of our own; Windows loopback capture; a low-latency or streaming model; any
claim about A/V sync (the sink is delayed by at least one window, always); playlists and
library management; EQ, VST, skins; a model picker; signing and notarisation (still
deferred, `roadmap.md:433`); `--splice` (still off, on the model's phase rather than on
anything here); bounded memory on the default first play (D13, 1.1); playhead-priority
rendering and seek-during-render (D14, 1.1).

## If it slips

In cut order: U3 (the report becomes a printed scorecard), U2's UI mapping (CLI only),
W1, K1 last (it is the only item whose exit depends on hardware we cannot test for you).
U1 and U4 do not get cut: one is the release's reason to exist, the other is what keeps
batch from filling the disk.
